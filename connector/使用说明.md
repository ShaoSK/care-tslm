# CARE to Compare 的 TimeNet connector：本地运行和提 PR

数据集 ID：`fraunhofer-iee/care-to-compare`，包含三个风场，共 95 个事件。

## 包里的文件

```
packages/timenet-connectors/src/timenet_connectors/datasets/fraunhofer_iee/
├── __init__.py
└── care_to_compare/
    ├── __init__.py        暴露 CONNECTOR
    ├── dataset.yaml       数据卡：许可、来源、描述、引用
    ├── source.py          解析和校验 CARE 原始文件（不依赖 TimeNet 类型）
    ├── connector.py       映射成 TimeNet 结构：Record / Signal / Annotation / Task
    └── tests/             基于合成数据的测试，含存储往返测试
scripts/build_farm_a.py    只转换风场 A 的快速验证脚本
PR_DESCRIPTION.md          PR 描述（英文，可以直接贴）
```

## 映射关系

| CARE | TimeNet |
|---|---|
| 每个事件 CSV | 1 个 Record，起点为文件的第一个时间戳 |
| 每个传感器统计量列（如 `sensor_11_avg`） | 1 个 Signal，10 分钟 RegularAxis，缺失的时间步和空单元格记为 null |
| `status_type_id` | 1 个 int8 Signal |
| feature_description | Signal 的 spec（描述 + 单位）；无法映射的单位记在 `source_unit` 注释里 |
| event_info | Record 级注释：风场、风机、事件标签、故障描述、故障部件 |
| train/prediction 段、事件窗口 | 区间型注释：`training_period` / `prediction_period` / `event_window` |
| 任务 | 事件检测分类（所有事件）、异常定位（异常事件）、故障部件分类（A、B 风场共 18 个事件） |

## 第 1 步：准备 TimeNet 仓库（需要 Python 3.11+ 和 uv）

```bash
# 先在 GitHub 上 fork OpenTSLM/TimeNet，再 clone 自己的 fork
git clone https://github.com/<你的账号>/TimeNet.git
cd TimeNet
make sync
make install-hooks
git checkout -b feature/care-to-compare
```

把本包里的 `packages/...` 目录原样复制到仓库根目录，和仓库里已有的 `packages/` 合并。

## 第 2 步：跑测试

```bash
make test-connectors
# 或者只跑这个 connector：
uv run pytest packages/timenet-connectors/src/timenet_connectors/datasets/fraunhofer_iee/care_to_compare/tests -v
make check     # ruff + ty 类型检查
```

## 第 3 步：用真实数据快速验证（只做风场 A，约 1–3 分钟）

```bash
# 下载 5.5 GB 的压缩包并解压，比如解压到 ~/data/
curl -L -o CARE_To_Compare.zip "https://zenodo.org/records/15846963/files/CARE_To_Compare.zip?download=1"
md5 CARE_To_Compare.zip           # 应为 2547b58c21ac8c242d13232860cf500c
shasum -a 256 CARE_To_Compare.zip # 记下来，第 4 步要用
unzip CARE_To_Compare.zip -d ~/data/

uv run python <本包>/scripts/build_farm_a.py ~/data/CARE_To_Compare
```

能打印出 `describe()` 的摘要，就说明真实数据能正常转换。

## 第 4 步：固定 SHA-256，然后完整构建

把第 3 步算出的 SHA-256 填进 `connector.py` 的 `ARCHIVE_SHA256`，然后：

```bash
timenet-build build fraunhofer-iee/care-to-compare --keep-cache
```

完整构建包括三个风场：下载 5.5 GB，解压后约 20 GB；风场 C 的解析大约需要 40 分钟到 1 小时。磁盘请预留 **约 40 GB**，其中解压文件约 20 GB，缓存的 .npy 约 12 GB，输出另算。

## 第 5 步：提交并提 PR

```bash
git add packages/timenet-connectors/src/timenet_connectors/datasets/fraunhofer_iee
git commit -s -m "feat(connectors): add fraunhofer-iee/care-to-compare"
git push origin feature/care-to-compare
```

在 GitHub 上向 `OpenTSLM/TimeNet` 提 PR，描述直接用 `PR_DESCRIPTION.md`。**这个 PR 链接就是比赛提交的第一项。**

## 我这边验证过的，以及没能验证的

**已验证：**

- 文件格式：直接读取了 Zenodo 压缩包里的真实文件，确认以 `;` 分隔，表头是 `time_stamp;asset_id;id;train_test;status_type_id;…`。抽查了风场 A 的事件 22 和风场 B 的事件 34：时间戳在 10 分钟网格上严格递增，偶尔有跳步；`id` 等于行号；训练段在前，预测段在后。风场 C 的列数是 957。
- `source.py` 的 7 个测试全部通过。
- 性能：一个和风场 C 同样大小的合成文件（952 列 × 5.5 万行）解析耗时 33 秒，峰值内存 736 MB。
- `connector.py` 的映射逻辑：用模拟的 TimeNet 接口跑通，区间、null、注释和任务都符合预期。

**没能验证：** 我的环境装不了 `timenet` 包（PyPI 和 GitHub 都被网络限制拦截了），所以 `connector.py` 和 `test_connector.py` 里对 TimeNet API 的调用，是按官方文档和现有 connector（har-cot、arfbench、hello-world）的写法写的，**还没有在真实环境里跑过**。第 2 步如果报错，大概率是这些地方的接口名或参数有出入：

- `record.annotations` / `annotation.key` / `annotation.span`
- `TimeInterval` 的相等比较
- `ureg.parse_units`

把报错发给我，我来改。
